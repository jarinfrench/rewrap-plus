Rewrap+

A VSCode extension — and companion CLI — that rewraps comments, docstrings, string literals, and (for Markdown and LaTeX) ordinary prose to a configured column limit, preserving formatted structure and emitting language-valid concatenation syntax on split.

Status: alpha. Python, JavaScript, TypeScript, TSX, C++, Java, Markdown, and LaTeX support (comments, docstrings, and string literals), plus comment-only support for TOML, Shell script (Bash), CSS, SCSS, and PowerShell, plus a CLI for scripting/pre-commit use — installable as a .vsix/npm install, not yet published to a marketplace or registry. See the changelog for what's shipped and what's known-missing.

The differentiator: Rewrap+ wraps string literals, not just comments — and when a literal has to split across lines, it emits whatever concatenation syntax the language actually needs (implicit adjacency, or a + operator, inserting grouping parentheses only where the surrounding syntax requires it). No other general-purpose VSCode comment wrapper attempts string-literal wrapping at all.

Features

  • Comments. Python line comments (#), grouped by contiguous same-indent blocks; JavaScript/TypeScript/TSX/C++/Java // line comments and both block-comment forms — a plain /* ... */ comment and the JSDoc/Doxygen/Javadoc-marked /** ... */ one. C++ additionally wraps Doxygen's /// repeated-marker doc comments. Directive comments (# noqa, // eslint-disable, // NOLINT, shebangs, and more) and anything that looks like commented-out code are left untouched rather than reflowed.
  • Docstrings and doc comments, with structure-preserving reflow across six documentation dialects plus plain paragraph reflow: Google and NumPy and Sphinx/reST (Python), JSDoc (JavaScript/TypeScript/TSX), Doxygen (C++), Javadoc (Java), plus Plain paragraph reflow. Dialect is detected per docstring/comment, not per file. Lists, fenced code blocks, doctest (>>>) blocks, and already-indented examples are preserved verbatim.
  • String literals — the differentiating feature. Long string literals split across multiple lines using whatever concatenation form the language actually needs, gated by a conservative prose heuristic (default: on) so paths, URLs, regexes, dict/object keys, SQL, and format-call arguments are left alone by default.
  • Directive comments for per-region opt-in/opt-out (# rewrap: off/on/ignore/force), honored alongside comment wrapping and string wrapping alike; Black's own # fmt: off/on is honored too.
  • Markdown wraps the document's own paragraphs — for Markdown, the prose is the document. Continuation lines always get a freshly-computed block-quote/list prefix; hard line breaks (trailing backslash, two-or-more trailing spaces, <br>) are preserved exactly.
  • LaTeX wraps ordinary prose the same way — % comment paragraphs wrap through the same path as Python's # comments. Sectioning commands, \item, hard breaks, and every verbatim/math environment (verbatim, tabular, equation, align, ...) are recognized and left untouched.

What this won't touch

Left byte-identical, deliberately, rather than risk mangling behavior:

  • Raw strings — Python's r"..."/byte strings b"...", and C++'s R"(...)".
  • Paths, URLs, regexes, SQL, dict/object/i18n keys, and format-call arguments (logging.info("%s failed", x)) — the prose heuristic scores these low and leaves them alone under the default policy.
  • Doctest blocks (>>> / ...) inside docstrings.
  • Commented-out code — detected via punctuation density and keyword shapes, left verbatim.
  • Template literals (`...`) in JavaScript/TypeScript/TSX — deferred, given ${} interpolation and significant internal whitespace.
  • Text blocks ("""...""", Java 15+) — the same grammar node as an ordinary string, but never wrapped.
  • Anything inside a C++ #define macro body — the parser treats a macro's body as opaque, unparsed text.
  • Any region overlapping a parse error — skipped with a reason, never partially edited.
  • File-final newline, trailing whitespace, and line endings (LF vs CRLF, detected per region) — preserved exactly as found.
  • In Markdown: headings, fenced/indented code blocks, tables, front matter, thematic breaks, HTML blocks (including HTML comments), link reference and footnote definitions, and $$ display-math paragraphs.
  • In LaTeX: every verbatim-like and math environment, every sectioning/structural command line, and a trailing % comment's own text.

See the extension README's full list for the complete, unabridged version.

Getting it

  • VSCode extension: not yet published to the Marketplace or Open VSX — download the latest .vsix from GitHub Releases and install it via Extensions: Install from VSIX....
  • CLI: not yet published to npm — clone the repo, run npm ci && npm run build, then see the @rewrap-plus/cli README for usage, flags, and configuration precedence.
